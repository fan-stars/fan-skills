# 分析生命周期

## 目标
让每次分析可恢复、可追踪并能说明扫描范围。

## 输入
九类强制上下文、用户模块范围、当前索引版本和上一运行记录。

## 执行步骤
生成唯一 run ID，加载上下文，确定边界，建立候选队列，递归追踪，更新索引，生成文档，执行门禁。`run_analysis.py` 固定执行 source、stale、symbol、route、table、module、business、quality-gates 顺序；失败后用原 ID 加 `--resume`，保留成功前缀并从第一个失败阶段继续。

## 输出
运行记录、索引、模块文档、stale 报告、未决问题和最终状态。

## 质量检查
区分扫描、内容读取、按索引复用、上下文文档读取和写入；`record_scope=AUTOMATED_PIPELINE` 不代表人工或模型的全部读取。状态与质量门禁一致。

## 失败处理
中途失败保留已原子提交的上一版索引，运行记为 `FAILED`。只有参数与项目根一致、阶段顺序有效且原记录为 FAILED 时允许 `--resume`；否则创建新 run ID。
