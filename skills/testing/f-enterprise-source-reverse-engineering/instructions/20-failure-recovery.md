# 失败恢复

## 目标
在扫描、解析、写入或源码变化后安全恢复。

## 输入
上一版索引、运行日志、临时文件、错误信息、当前源码哈希和 stale 报告。

## 执行步骤
保留上一版，清理孤立临时文件，定位失败阶段；对同一 project/module/root 使用原 `analysis_run_id` 执行 `python3 scripts/run_analysis.py ... --resume`，从首个失败阶段继续。单文件变化先增量刷新；源码或 source-index 在失败后已变化时应创建新运行并重新验证证据。

## 输出
FAILED/PARTIAL 运行记录、恢复动作、受影响模块、需复核文档和下一步命令。

## 质量检查
确认没有写入业务源码，索引可解析且原子替换完整，旧证据未被静默重写；恢复后阶段列表必须仍是固定顺序且无重复，`resume_count` 与 `resumed_at` 数量一致。

## 失败处理
连续失败时停止扩展范围并请求修复路径、权限或依赖，不用降级结果冒充完成。
